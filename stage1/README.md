# Stage 1 — TinyMPC 군집: 이동 편대 스윕 커버리지 + 동적 장애물

Qi et al. (RA-L 2022) 식 (10)의 가중합 `U = k1·u^f − k2·Σu^c − k3·Σu^o`에서
반발력(식 5)과 split-merge 조향(식 7~9)을 없애고, **TinyMPC 한 문제의 비용과 제약**으로 옮긴다.
임무는 Crazyflie 군집이 횡대 편대로 영역을 훑는 **스윕 커버리지**이고, 도중에 정적·동적 장애물을 만난다.

- 1단계(알고리즘 완성): 이 문서의 "알고리즘"
- 2단계(시뮬레이션 검증): Python 시뮬레이션(`main.py`) 결과는 "결과" 절, Crazyswarm2 SIL(`sil/`)은 실행 준비 완료(미실행)

## 알고리즘

### 1. 예측 모델 — Qi 식 (1)의 병진부
`ṗ = v, v̇ = U^d` → 영차 홀드 이산화 이중적분기 `x = [p, v] ∈ R⁴`, `u ∈ R²` (`model.py`).
고도는 하위 제어기(Mellinger)가 일정하게 유지한다고 가정한다.

### 2. 비용 — Qi 식 (4) 편대 추종의 대체
```
min Σ_{k=0}^{N-2} ½‖x_k − c_k‖²_Q + ½‖u_k‖²_R + ½‖x_{N-1} − c_{N-1}‖²_{P_f}
```
참조 `c_i(t) = 편대중심(t) + 오프셋_i`는 **스윕 경로**(`scenario_sweep.py`)에서 나온다.
- 편대: 진행 방향에 수직인 횡대. 간격 = 센서 폭 − 겹침(0.6 m). 한 번에 덮는 폭(swath) = M·간격.
- 경로: 부스트로페돈(lawnmower). 레인 끝에서 횡대 방향으로 한 swath만큼 옆걸음하므로 편대를 회전할 필요가 없다.
- 속도: 구간마다 코사인 램프 0→v→0. 참조가 C¹이라 Qi 기준선의 피드포워드 `v̇_ci`도 해석적으로 정의된다.

`K_1^f, K_2^f` 게인의 역할은 Q, R이 맡는다. MPC는 호라이즌 동안의 미래 참조를 미리 안다(Qi는 현재값만 쓴다).

### 3. 제약 — Qi 식 (5)·(7)~(9)의 대체 (`constraints.py`)
모든 회피 제약을 **시변 반공간** 하나의 형태로 통일한다.
```
n'·p(t_k) ≥ b0 + b1·t_k          (knot k 마다 우변이 다르다)
```
등속으로 움직이는 이웃·장애물의 위치가 t에 대한 1차식이라, 정적/동적을 이 형태 하나로 다룬다.

| 대상 | 법선 n | 우변 | 대체하는 Qi 항 |
|---|---|---|---|
| 기체 간 (분산) | 현재 상대위치 방향 | 두 기체 중점 `m0 + v̄·t`에서 `r_safe/2`만큼 (**이동 BVC**) | 식 (5) 반발+댐핑 |
| 기체 간 (중앙) | 현재 상대위치 방향 | `n'(p_i − p_j) ≥ r_safe` (두 궤적 동시 결정) | 식 (5) |
| 장애물 | **CPA 빗나감 벡터** 방향 (상대운동에 수직) | `n'(o0 + v_o·t) + clearance` | 식 (7)~(9) split 조향 |
| 속도·입력 | 정팔각형(꼭짓점이 원 위) | `‖v‖ ≤ v_max`, `‖u‖ ≤ u_max` | 식 (10) 뒤의 성분별 clip |

- **이동 BVC**: 두 기체가 같은 `n, m0, v̄`를 대칭으로 계산하므로 두 제약을 더하면 `n'(p_i − p_j) ≥ r_safe`가 된다. 교환 정보는 현재 위치·속도(기체당 16 B)로, Qi 식 (5)가 쓰는 정보와 같다. 정적 BVC(`v̄ = 0`)는 편대 전체가 전진할 때 셀이 제자리에 묶여 추종이 느려진다(절제 실험 `dist-static`).
- **CPA 법선 = split-merge**: 각 기체가 장애물의 상대 진행선에서 자기가 이미 있는 쪽으로 비킨다. 그래서 편대가 양옆으로 갈라지고(split), 장애물이 멀어지면 제약이 풀려 추종 비용이 다시 모은다(merge). 정면 충돌(빗나감 ≈ 0)이면 편대 안에서의 자기 쪽(`side_hint`)으로 비켜서 매 주기 방향이 뒤집히는 진동을 막는다.
- **감지 반경** `R_p`(Qi 식 6의 거리 조건) 안의 장애물만 제약으로 넣는다. 시야각 조건은 두지 않았다(전방위 인식을 가정).

**실현 가능성 보정** — ADMM은 실현 불가능한 문제에서 쌍대변수가 누적되어 발산한다(실제로 관측됨).
1. 램프: 필요한 여유 `h(t) = h0 + s·t`. `h0 = min(목표, 현재 여유)`로 두고, 부족분은 `t_recover`(장애물은 `t_cpa`) 안에 기울기 s로 채운다.
2. 제동 여유: 제약된 양이 요구 속도 b1보다 느리게 늘고 있으면 `(b1 − 현재 속도)²/(2a)`만큼 b0를 낮춘다.
3. 요구 속도 상한: b1 ≤ 0.9·v_max. 장애물이 기체보다 빠르게 덮치면 보장을 잃는다(`urgent`로 기록).

### 4. 솔버 — TinyMPC 알고리즘 (`tinyadmm.py`)
TinyMPC(Nguyen et al., ICRA 2024)와 같은 구조다.
- 오프라인: `(Q+ρI, R+ρI)`로 무한 호라이즌 Riccati를 풀어 `K∞, P∞, Quu⁻¹, (A−BK)ᵀ`를 캐시한다.
- 온라인 ADMM 한 반복: 롤아웃 → 슬랙 투영(팔각형은 닫힌 식, 반공간은 Dykstra) → 쌍대 갱신 → 선형 비용 → 역방향 패스(벡터 연산만). 행렬 분해는 하지 않는다.
- 차이점: **knot별 시변 반공간을 기본으로 지원**하고, 종단 선형항을 `−(P∞ − ρI)·c`로 맞춰 "ADMM 고정점 = 위에 적은 QP의 최적해"가 정확히 성립하게 했다(`P_f = P∞ − ρI`).
- 검증: `tools/check_admm.py`가 같은 QP를 OSQP로 정확히 풀어 비교한다. 4가지 경우(무제약, 팔각형, 움직이는 벽, 반공간 2개) 모두 위치 오차 1 mm 미만, 제약 위반 0.4 mm 미만.
- 설정: ρ = 20, 반복 예산 100회(MCU에서처럼 고정 예산), 잔차 기준 1e-2, 직전 해를 한 칸 밀어 warm start.

### 5. 1-스텝 안전 필터 — 제동거리 barrier (`controller_tiny._safety_filter`)
반복 예산에서 끊긴 ADMM 해는 제약을 덜 지킨 채 나올 수 있다. 편대 형성 중 교차에서 실제로 안전거리 위반이 났고(시드 2·3·4), 반복을 3배로 늘려도 없어지지 않았다.
그래서 MPC가 무엇을 내든 마지막에 한 번 거른다.
- 각 반공간 `g = n'p − b(t)`에 대해 `B = g − max(0, −ġ)²/(2a)` ("지금 제동하면 멈출 수 있다")를 다음 스텝에서 지키게 한다.
- `B(x₁)`는 `σ = n'u`에 대해 단조 증가다. 그래서 조건이 **u 공간의 반공간 하나** `n'u ≥ σ_min`이 된다(이산 시간 CBF와 같은 구조, 선형이라 QP가 필요 없다).
- 이 반공간들과 입력·속도 팔각형의 교집합에 u를 최소 수정으로 투영한다. 분산형은 2차원 투영이라 MCU에서도 수 µs 수준이다.
- 개입 빈도: cf 프로파일 10시드 기준 분산형 2.7%, 중앙집중형 6.1%.

### 6. 한 제어 주기 (분산형, 기체 i의 온보드 계산)
```
1. 수신: 이웃 j의 (p_j, v_j), 감지 반경 안 장애물의 (o, v_o, r)
2. 참조 c_i[0..N-1] ← 스윕 경로 (편대 중심 + 오프셋_i)
3. 반공간: 이웃마다 이동 BVC, 장애물마다 CPA 반공간 (+ 램프, 제동 여유)
4. TinyMPC ADMM (warm start, 반복 예산 100)
5. 안전 필터: u0 ← barrier 반공간 ∩ 팔각형 으로 투영
6. 출력: cmdFullState(예측 x_1의 위치·속도, 가속도 피드포워드 u0)
```
중앙집중형은 같은 솔버·같은 제약 기하를 상태 4M에 쌓아 한 번에 푼다. 비교되는 것은 "구조 차이"뿐이다.

### Qi 식과의 대응
| Qi et al. | Stage 1 |
|---|---|
| 식 (4) consensus 편대 추종 | 비용 `‖x − c‖²_Q` (미래 참조 포함) |
| 식 (5) Hooke+damping 반발 | 이동 BVC 반공간 + barrier 필터 |
| 식 (6) 부채꼴 감지 | 감지 반경 `R_p` (시야각은 생략) |
| 식 (7)~(9) split 조향 | CPA 빗나감 방향 반공간 — 갈라짐·합침이 제약에서 자연히 나온다 |
| 식 (10) 가중합 + clip | 하나의 최적화 + 정팔각형 크기 제한 |
| 식 (11) 자세 변환 | Crazyflie 펌웨어 Mellinger (cmdFullState) |

## 공식 `tinympc` 패키지를 쓰지 않은 이유
처음에는 공식 파이썬 패키지(`pip install tinympc`, 0.0.8)로 시작했다. 확인된 사실은 다음과 같다.
1. 파이썬 API에 **시변 선형 제약이 없다**(C++ 코어에는 `tv_Alin_x`가 있다). 선형 제약이 호라이즌 전체와 k=0에 같은 행렬로 걸린다. 시계 상태 τ를 붙여 우회하려 했으나 폐루프에서 발산했다.
2. SOC는 `‖u_head‖ ≤ μ·u_last`(마찰 원뿔) 형태라 `‖u‖ ≤ u_max`에는 쓸 수 없다.
3. **해가 명시한 QP의 최적해와 달랐다**: 무제약 문제에서 반복을 5000회로 강제해도 u0 = 1.735(정확한 LQR은 8.722). 걸리지도 않는 선형 제약 1줄(`px ≤ 100`)을 넣자 1.925로 바뀌었다.

비교 실험의 전제가 "MPC가 자기 문제를 제대로 푼다"이므로, OSQP로 검증할 수 있는 직접 구현으로 전환했다.
재현: `python3 tools/check_tinympc.py`(tinympc 설치 필요). 사용법상 실수일 가능성을 완전히 배제하지는 못했다. upstream에 문의할 때 이 스크립트를 그대로 쓰면 된다.

### 해석
- 안전: 제안 방식(분산·중앙)은 모든 시드에서 기체 간·장애물 위반이 0이다. 최소값이 경계에 정확히 붙는다. 다만 이 보장은 **안전 필터에 기대고 있다**. 필터 없이 미수렴 ADMM 해를 그대로 쓰면 편대 형성 교차에서 위반이 났다.
- 커버리지: 장애물 회피로 생기는 구멍이 Qi 대비 1/5 수준이다. 손실은 장애물 바로 뒤의 작은 조각뿐이다(`overview.png`의 빨강).
- 분산 vs 중앙: 이 규모(4기)에서는 성능이 거의 같다. 중앙형은 문제가 커서 미수렴·필터 개입이 더 잦고, PC 계산 시간도 4~5배다.
- 이동 BVC vs 정적 BVC: 안전은 같지만 정적 BVC는 전진 중 셀이 묶여 편대 오차와 복귀 시간이 늘어난다.

## 한계와 다음 단계
1. **SIL 미실행** — 파일은 준비됐고 오프라인 평가 경로만 확인했다. 모델 오차·속도 추정·계산 지연의 영향은 SIL에서 처음 드러난다.
2. **반복 예산 안 수렴 15~25%** — 안전은 필터가 지키지만 계획 품질은 예산에 민감하다. 적응 ρ, 스케일링, 더 나은 warm start가 후보다.
3. **장애물 시나리오 고정** — 시드가 이륙 배치만 바꾼다. 장애물 위치·속도·개수를 무작위화한 통계가 필요하다.
4. **인식 = 참값** — 장애물 상태에 잡음·지연을 넣지 않았다. CPA 법선은 속도 추정 오차에 민감할 수 있다.
5. **편대 형성 교차** — 분산 BVC는 기체들이 서로 가로질러 재배치할 때 느리다(qi14 시드 4). 형성 단계 슬롯 배정(거리 최소화)이 표준 해법이다.
6. **MCU 이식** — 반복당 연산은 벡터 연산뿐이지만, STM32F405의 실제 시간·메모리는 재지 않았다. 공식 TinyMPC C 코드에 knot별 반공간 투영과 barrier 필터를 넣는 방향이다.
7. **Qi 기준선 게인** — 실내 규모로 옮길 때 길이 척도 규칙 하나만 적용했다(`baselines.qi_gains_for`). 더 튜닝하면 기준선 성능이 올라갈 수 있다.
8. **2D 가정** — 고도는 하위 제어기가 잡는다. downwash(수직 간섭)는 모델링하지 않았다.
